### 2. SEO-индексация перед публичным запуском

**Контекст:** приложение — Vite + React SPA. Яндексбот практически не рендерит JS, поэтому без pre-rendering лендинг не проиндексируется. Все шаги ниже — обязательные, выполнять последовательно.

**Шаг 1 — Pre-rendering лендинга (`vite-plugin-prerender`):**
Установить `vite-plugin-prerender`, настроить рендер маршрутов `/`, `/privacy`, `/terms` при сборке. После этого nginx отдаёт Яндексботу готовый HTML вместо пустого `<div id="root">`.
```bash
npm install vite-plugin-prerender --save-dev
```
Добавить в `vite.config.ts` и прописать список pre-render маршрутов. App-маршруты (`/books/*`) не трогать — они за `AuthGuard`.

**Шаг 2 — Meta-теги (`react-helmet-async`):**
Установить `react-helmet-async`, обернуть `App.tsx` в `<HelmetProvider>`, добавить в `Landing.tsx`:
- `<title>` и `<meta name="description">` — основные
- `<meta property="og:title/description/image">` — для ВКонтакте и мессенджеров
- `<link rel="canonical" href="https://avtorstudio.com/">`
- `<meta name="robots" content="noindex">` — в Auth, Dashboard и всех `/books/*` страницах
- `<meta name="yandex-verification" content="...">` — код получить в Яндекс.Вебмастер

**Шаг 3 — `robots.txt` и `sitemap.xml`:**
Проверить `public/robots.txt` — там не должно быть `Disallow: /`. Создать `public/sitemap.xml` с записями для `/`, `/privacy`, `/terms`.

**Шаг 4 — Яндекс.Вебмастер:**
Зарегистрировать сайт `avtorstudio.com` → добавить sitemap → проверить индексацию через «Инструменты» → «Проверить URL». Это главный инструмент мониторинга для RU-рынка.

**Шаг 5 — Яндекс.Метрика:**
Создать счётчик, добавить скрипт в `index.html`. Яндекс.Метрика — поведенческий сигнал ранжирования в Яндексе (CTR, время на сайте). Без неё сигналы не передаются.

**Шаг 6 — Google Search Console:**
Добавить сайт, загрузить sitemap — параллельно с Яндексом. Google умеет JS, но pre-rendering ускоряет индексацию.

> 🛠 **Скиллы:** `/ai-seo` и `/seo-audit` из `marketingskills` — для аудита после индексации; `/site-architecture` — если понадобится расширить структуру публичных страниц.

### 3. ЮKassa — платёжный провайдер

**Что это:** без платёжной системы нет монетизации. ЮKassa поддерживает самозанятых (4% с физлиц), работает без ИП. Нужна Edge Function для приёма вебхуков от ЮKassa и обновления поля `plan` в таблице `profiles`.

**Что сделать:** зарегистрироваться в ЮKassa, получить `shop_id` и `secret_key` → создать Supabase Edge Function `yukassa-webhook` → при успешной оплате обновлять `profiles.plan = 'pro'` и `profiles.plan_expires_at`. При регистрации включить партнёрскую интеграцию с ФНС — чеки для самозанятых формируются и отправляются клиентам автоматически, бесплатно.

### 4. Оферта, акцепт и подтверждение оплаты (при запуске ЮKassa)

**Что это:** три юридических требования при приёме денег онлайн. Без них штраф 3 000–4 000 ₽ за каждое нарушение.

- **Оферта** — страница `/offer`: что продаётся, цена, как отменить подписку.
- **Акцепт** — кнопка «Оплатить» должна содержать текст «Нажимая, вы соглашаетесь с условиями оферты» со ссылкой.
- **Подтверждение заказа** — после оплаты отправить email с номером транзакции (через Supabase Edge Function + Resend/Postmark).

### 11. Расширенная проверка орфографии + пользовательский словарь

**Что это:** сейчас проверка орфографии — браузерная (`spellcheck`). Браузер не знает авторских имён, выдуманных топонимов, терминов фэнтези-мира — подчёркивает их красным. LanguageTool API умеет стилистику, пунктуацию, согласование — полноценный аналог Grammarly на русском.

**Проблемы зафиксированные при тестировании:**
1. ~~При исправлении одного слова мигают подчёркивания у остальных~~ — ✅ закрыто, точечное удаление декораций.
2. Нет возможности добавить слово в словарь — «Дэмиен», «Арвен», «Серебряный Лес» будут подчёркиваться вечно.

**Что сделать (по приоритету):**
1. **Пользовательский словарь:** в контекстном меню подчёркнутого слова добавить пункт «Добавить в мой словарь». Хранить как `user_dictionary text[]` в `profiles`. При загрузке редактора — передавать словарь в TipTap, игнорировать эти слова при проверке.
2. **LanguageTool (потом, Pro-план):** TipTap-расширение поверх LanguageTool API. Подсветка ошибок → контекстное меню с исправлениями.

> 🛠 **Скилл:** `/systematic-debugging` — для пользовательского словаря в TipTap нужно корректно расширить схему; скилл помогает не сломать существующий spellcheck-flow.

### 36. Снапшот при смене статуса главы — нужно ли объединять?

**Что это:** сейчас статус главы (черновик / в работе / готово) меняется кликом в Структуре и в сайдбаре режима Манускрипт. Named Snapshots — отдельная механика в правой панели редактора. Вопрос: стоит ли связать эти два действия?

**Варианта два, нужно обдумать:**

1. **Авто-тост при смене на «Готово»:** при переводе главы в статус «Готово» — показывать ненавязчивый тост «Зафиксировать версию?» с кнопкой «Сохранить». Нажал — создаётся именованный снапшот «Готово · [дата]» без открытия панели версий. Отклонил — ничего не происходит.

2. **Оставить раздельно:** статус — это пометка для навигации и структуры, снапшот — точка возврата текста. Разные цели, разные триггеры. Объединение создаёт неожиданное поведение.

**Что нужно решить перед реализацией:**
- Насколько часто автор меняет статус туда-обратно? Если часто — тост будет раздражать.
- Именованные снапшоты сейчас только Pro. Тост тогда только для Pro-пользователей — это понятно?
- Где технически перехватить смену статуса: в `updateChapter()` из `Outline.tsx` или в отдельном обработчике?

**Не делать сейчас.** Вернуться после того как появятся реальные пользователи — они покажут, хотят ли они этого сами.

### 38. Ambient Sounds — заменить синтетические звуки на реальные записи

**Что это:** сейчас `public/sounds/*.wav` — это синтетический шум (белый/розовый/коричневый), сгенерированный скриптом Node.js. Для продакшена нужны реальные атмосферные записи.

**Что сделать:**

1. Зайти на [freesound.org](https://freesound.org) (бесплатный аккаунт).
2. Найти и скачать 5 звуков с лицензией **CC0** или **CC BY** (Attribution). Искать по запросам:
   - `cafe ambience loop` → сохранить как `cafe.wav`
   - `rain ambience loop` → `rain.wav`
   - `forest birds ambience` → `forest.wav`
   - `fireplace crackling loop` → `fire.wav`
   - `white noise` → `noise.wav`
3. Скачать в формате **WAV или MP3**. Если MP3 — переименовать расширение в `.wav` (браузер читает оба формата по содержимому), либо обновить расширения в `src/components/StatusBar.tsx` в массиве `SOUNDS` (строки 15–21).
4. Положить файлы в `public/sounds/`.
5. Рекомендуемая длина: **60–120 секунд** (loop будет незаметнее швов). Размер до 3MB на файл.

**Альтернативный источник (проще):** [pixabay.com/sound-effects](https://pixabay.com/sound-effects/) — скачивание без регистрации, лицензия CC0. Искать `rain loop`, `cafe background`, `forest ambience`, `fireplace`, `white noise`.

**Проверка после замены:**
```
npm run dev
# Открыть http://127.0.0.1:5273/books/<ID>/editor
# Кликнуть иконку наушников в правом углу StatusBar
# Выбрать звук → должен заиграть плавно (fade in 0.5s)
# Переключить на другой → crossfade
# Кнопка «× Стоп» → fade out
```
