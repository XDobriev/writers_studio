## Задачи — от критичного к некритичному

### 1. Уведомление Роскомнадзора ⚠️

**Что это:** по закону ФЗ-152 любой сайт, собирающий данные пользователей (email, имя), обязан зарегистрироваться как оператор персональных данных. Штраф за отсутствие — ~5 000 ₽, но при проверке могут быть последствия серьёзнее.

**Что сделать:** зайти на pd.rkn.gov.ru, заполнить форму (~30 минут). Указать: оператор — физлицо (ФИО), цель обработки — регистрация и авторизация пользователей, категории данных — email.

---

### 2. GitHub Flow — защита прода

**Что это:** сейчас все коммиты идут напрямую в `main`, который сразу деплоится на прод. Один сломанный коммит = сломанный прод для реальных пользователей. После запуска это неприемлемо.

**Что сделать:** новые фичи делать в `feature/xxx`-ветках, мержить в `main` только после проверки. Добавить ручную проверку golden path перед каждым мержем: войти → открыть книгу → написать текст → убедиться, что всё работает.

---

### 3. ЮKassa — платёжный провайдер

**Что это:** без платёжной системы нет монетизации. ЮKassa поддерживает самозанятых (4% с физлиц), работает без ИП. Нужна Edge Function для приёма вебхуков от ЮKassa и обновления поля `plan` в таблице `profiles`.

**Что сделать:** зарегистрироваться в ЮKassa, получить `shop_id` и `secret_key` → создать Supabase Edge Function `yukassa-webhook` → при успешной оплате обновлять `profiles.plan = 'pro'` и `profiles.plan_expires_at`.

---

### 4. Оферта, акцепт и подтверждение оплаты (при запуске ЮKassa)

**Что это:** три юридических требования при приёме денег онлайн. Без них штраф 3 000–4 000 ₽ за каждое нарушение.

- **Оферта** — страница `/offer`: что продаётся, цена, как отменить подписку.
- **Акцепт** — кнопка «Оплатить» должна содержать текст «Нажимая, вы соглашаетесь с условиями оферты» со ссылкой.
- **Подтверждение заказа** — после оплаты отправить email с номером транзакции (через Supabase Edge Function + Resend/Postmark).

---

### 5. Lifetime deal — 50 мест

**Что это:** при публичном анонсе предложить первые 50 мест за 4 900 ₽ (вместо 290 ₽/мес × навсегда). Ограниченность создаёт срочность. После 50 продаж — убрать Lifetime, оставить только месячный/годовой планы.

**Что сделать:** добавить поле `lifetime_slots_remaining integer` в таблицу `settings` (или как env). Показывать счётчик на лендинге и в модалке апгрейда: «осталось X мест». Декрементировать через вебхук ЮKassa при каждой Lifetime-покупке.

---

### 6. Грандфазеринг — заморозка цены для первых пользователей

**Что это:** первые ~100–200 пользователей на месячном плане должны навсегда платить 290 ₽, даже когда цена поднимется до 390 ₽. Это стимул для ранней регистрации и обязательство перед аудиторией.

**Что сделать:** добавить поле `grandfathered boolean default false` в таблицу `profiles`. Выставлять `true` при создании подписки в Фазе 1. Биллинговая логика: если `grandfathered = true` → списывать 290 ₽, иначе → актуальная цена.

---

### 7. Соавторство — публичная ссылка (read-only)

**Что это:** сейчас книгу нельзя показать никому без входа в аккаунт. Нужна возможность поделиться ссылкой для просмотра без регистрации — как в Google Docs.

**Что сделать:** добавить поле `share_token uuid` в таблицу `books`. Маршрут `/share/{token}` открывает книгу без авторизации, только чтение. Кнопка «Поделиться» в Chrome.tsx генерирует токен и копирует ссылку. RLS-политика: `share_token IS NOT NULL` → разрешить SELECT без `auth.uid()`.

---

### 8. Соавторство — приглашение редактора

**Что это:** владелец книги может пригласить другого пользователя редактировать. Нужна таблица `book_collaborators` с ролями `editor | viewer`.

**Что сделать:** миграция — таблица `book_collaborators (book_id, user_id, role, invited_by, created_at)`. Владелец вводит email → создаётся pending-запись → пользователь получает email с ссылкой → принимает приглашение. RLS: `auth.uid() = user_id OR EXISTS (SELECT 1 FROM book_collaborators WHERE book_id = ... AND user_id = auth.uid())`.

---

### 11. Перетаскивание глав в Доске

**Что это:** в режиме Доска (Corkboard) карточки глав нельзя менять местами drag & drop — только через контекстное меню (Вверх/Вниз). Это неудобно при переструктурировании.

**Что сделать:** краткосрочно — добавить кнопки ↑/↓ в контекстное меню карточки Доски (они уже есть в Структуре). Долгосрочно — drag & drop через `@dnd-kit/core` (уже используется в Структуре, можно переиспользовать).

---

### 12. Изменение размера панели заметок

**Что это:** панель «Заметки на полях» (`NotesPanel`) имеет фиксированную ширину. Это неудобно в узком окне (панель перекрывает текст) и в широком (слишком много пустого пространства).

**Что сделать:** три фиксированных ширины S / M / L, переключатель в шапке панели (иконки или radio). Сохранять выбор в `localStorage` с ключом `notes-panel-size`. Применять через CSS-класс `.notes-panel--sm / --md / --lg`.

---

### 13. Экспорт DOCX

**Что это:** сейчас экспорт только в TXT и базовый HTML. DOCX нужен авторам, которые сдают рукописи в издательства или редакторам — это стандартный формат.

**Что сделать:** библиотека `docx` (npm). Структура: титульная страница (название, автор, жанр из `books`), оглавление, главы с разделителями. Форматирование TipTap-разметки → DOCX-стили (bold, italic, заголовки).

---

### 14. Экспорт FB2

**Что это:** FB2 — основной формат электронных книг в РФ (Litres, FBReader, PocketBook). Для авторов, публикующих на Litres — критически нужен.

**Что сделать:** без сторонних библиотек — сгенерировать XML вручную. Структура: `<FictionBook>` → `<description>` (метаданные) + `<body>` с `<section>` на каждую главу. Экранировать HTML из TipTap.

---

### 15. Экспорт EPUB

**Что это:** стандарт для международных ридеров (Apple Books, Kobo, Kindle через конвертер). Нужен для авторов, выходящих за пределы Litres.

**Что сделать:** библиотека `epub-gen` или собрать вручную (EPUB = zip с HTML + OPF + NCX). Метаданные из `books`, обложка из Storage, разбивка на главы.

---

### 16. Горизонтальная хронология

**Что это:** раздел «Хронология» (`Timeline.tsx`) сейчас показывает события списком. Для работы с хронологией произведения нужна визуальная ось времени — события по порядку (`pos` из `timeline_events`) на горизонтальной ленте.

**Что сделать:** сначала ресёрч библиотек: `vis-timeline`, `react-chrono`, кастомный SVG. Нужны: создание событий с датой/периодом, группировка по персонажам/аркам, drag по оси. Провести ресёрч перед реализацией.

---

### 17. Графическая карта мира

**Что это:** раздел «Карта» (`Map.tsx`) сейчас показывает локации списком. Для фэнтези и sci-fi авторов нужна визуальная карта, где можно рисовать регионы и расставлять метки.

**Что сделать:** сначала ресёрч: Leaflet с кастомными тайлами, Excalidraw, Konva.js, tldraw. Нужны: свободное рисование регионов, метки/локации с `x/y` из `locations`, слои. Провести ресёрч перед реализацией.

---

### 18. Playwright e2e — базовый тест

**Что это:** нет автоматических тестов. Каждый деплой — риск. Один базовый тест покрывает критический путь и ловит регрессии.

**Что сделать:** `npm i -D @playwright/test && npx playwright install chromium`. Один тест: логин → создание книги → редактор открылся → напечатать текст → текст сохранился. Запускать перед каждым деплоем в `main`.

---

### 19. Аналитика онбординга в БД

**Что это:** флаг «пользователь прошёл онбординг» сейчас в `localStorage`. При смене браузера или устройства — онбординг показывается снова. При 50+ пользователях нельзя анализировать воронку.

**Что сделать:** добавить `onboarded_at timestamp` в таблицу `profiles`. При завершении онбординга — записывать дату в БД. `localStorage` оставить как кэш для быстрой проверки.

---

### 20. Admin-панель: графики и retention

**Что это:** в admin-панели сейчас таблицы пользователей. Нет графиков роста (DAU/WAU/MAU), retention (% вернувшихся через 7/30 дней), топ по активности, аномалий (пользователи без книг, без активности 60+ дней).

**Что сделать:** добавить вкладку «Аналитика» в admin. Графики через `recharts` (уже в зависимостях?). SQL-запросы в Supabase Edge Functions — не тяжёлые join-ы на фронте.

---

### 21. Версии главы — git-like rollback

**Что это:** сейчас нет истории изменений. Если автор случайно удалил текст и не нажал Ctrl+Z — всё потеряно. Autosave перезаписывает без версий.

**Что сделать:** сначала спросить у реальных пользователей: достаточно ли undo/redo или нужна история по датам. Если нужна — таблица `chapter_versions (chapter_id, content, created_at)`, автосохранение снимка каждые N минут или при закрытии.

---

### 22. Обернуть Supabase-вызовы в сервисный слой

**Что это:** `supabase.from(...)` вызывается напрямую в компонентах по всему проекту. Сложно тестировать, сложно менять структуру запросов, дублирование логики.

**Что сделать:** создать `src/lib/api/booksApi.ts`, `chaptersApi.ts`, `charactersApi.ts` и т.д. Не переписывать всё сразу — мигрировать при следующем касании каждого файла.

---

### 23. Несогласованный useCallback в редакторе

**Что это:** в `Editor.tsx` все обработчики обёрнуты в `useCallback`. В `RichEditor.tsx` функции `applyColor`, `runFmt`, `applySuggestion` — обычные функции. Это не баг, но стиль непоследователен и может вызывать лишние ре-рендеры.

**Что сделать:** при следующем касании `RichEditor.tsx` обернуть эти три функции в `useCallback`.

---

### 24. Мобильная версия редактора — полный адаптив

**Что это:** базовый мобильный адаптив есть (навигация, drawer, hamburger). Но редактор в полноэкранном режиме на телефоне не оптимизирован — тулбар не влезает, боковые панели не работают.

**Что сделать:** ревизия `EditorHybrid.tsx` и `Chrome.tsx` на ширинах < 480px. Минимум: редактор + список глав + дэшборд должны работать без горизонтального скролла.

---

### 25. Расширенная проверка орфографии

**Что это:** сейчас проверка орфографии — браузерная (встроенная `spellcheck`). LanguageTool API умеет стилистику, пунктуацию, согласование — полноценный аналог Grammarly на русском.

**Что сделать:** TipTap-расширение поверх LanguageTool API (бесплатный tier есть). Подсветка ошибок → контекстное меню с исправлениями. Только Pro-план.

---

### 26. Соавторство — real-time редактирование

**Что это:** два пользователя редактируют одну главу одновременно, видят курсоры друг друга. Самая сложная фича соавторства — требует Y.js + TipTap Collaboration Extension.

**Что сделать:** реализовывать не раньше 100 платящих пользователей. Варианты бэкенда: Supabase Realtime с Y.js, Hocuspocus на Fly.io/Timeweb. TipTap v3 поддерживает Y.js нативно.

---

### 27. Хостинг в РФ

**Что это:** Vercel работает из США. При жалобах на доступность или при требованиях ФЗ-152 (хранение данных россиян на серверах в РФ) нужен переезд.

**Что сделать:** мониторить жалобы пользователей. При необходимости — Timeweb Cloud App Platform или VPS (Beget, Selectel). Supabase при этом может остаться (EU-регион).
