### Счётчик «сегодня» показывает накопленный объём вместо дневного прироста
**Симптом:** в статусбаре редактора «сегодня · N слов» показывает суммарный объём книги вместо реально написанного за день (пользователь написал 3 слова, счётчик показывает 1 272).
**Воспроизвести:** 1. Открыть книгу после дня перерыва (вчерашней записи в `writing_snapshots` нет) → 2. Написать несколько слов → 3. Ожидаю «3 слова за сегодня», вижу полный объём книги.
**Корень проблемы:** `src/lib/useWritingStats.ts:36` — `ydayTotal = snap[ydayStr] ?? 0`. Если вчера не было сессии, снэпшот отсутствует → `ydayTotal = 0` → `todayWords = today_total - 0 = всё накопленное`. Не лечить симптом патчем на одну строку — нужно найти ближайший снэпшот до сегодня (не обязательно вчера).
**Файлы:** `src/lib/useWritingStats.ts:24-53` (функция `computeStats`, строка 36 — главный дефект)
**Фикс:** заменить `snap[ydayStr] ?? 0` на поиск последней записи с датой < today: `data.filter(r => r.date < todayStr).sort().at(-1)?.words ?? 0`.
**Проверить:** написать слово после дня пропуска → счётчик «сегодня» = 1 (а не total книги).

## Задачи — от критичного к некритичному

### 0. Дизайн и UX — открытые вопросы для решения

#### Выравнивание текста в редакторе (justify vs left)
**Вопрос:** сейчас в `.sheet p` используется `text-align: start` (`src/styles/design-system.css:471`). Правый край текста рваный с большим количеством переносов строки.
**Рекомендация:** для художественной прозы стандарт — `text-align: justify` с `hyphens: auto`. Именно так работают Word, Kindle, все издательские системы. Рваный правый край — норма для интерфейсных текстов, а не для страницы книги. Переключиться на `justify` в `.sheet p`.
**Файлы:** `src/styles/design-system.css:471` — одна строка изменения.

#### Режимы абзацев в экспорте — верификация работы
**Вопрос:** «Красная строка» (indent) и «Интервал» (spacing) — задают разные CSS/DOCX-стили. Пользователь не видит разницы при экспорте.
**Исследовать:** 1) Открыть экспортированный EPUB в Calibre/браузере — виден ли отступ первой строки в режиме indent? 2) DOCX — открыть в Word, проверить отступы абзацев. Код: `src/pages/Export.tsx:142-145` (CSS), `:257-265` (DOCX).
**Ожидаемое поведение:** indent — первая строка с отступом 1.4em, без пробела между абзацами; spacing — без отступа, с пробелом ~1.1em между абзацами.

#### HTML-экспорт — нужен ли пользователям
**Вопрос:** зачем экспорт в HTML, когда есть EPUB/DOCX?
**Вывод (не спорный):** HTML обоснован — копирайтеры размещают текст на сайтах, пользователи конвертируют через Pandoc, разработчики переиспользуют в других инструментах. Это стандарт у Scrivener и Ulysses. Оставить, но добавить описание «для публикации на сайте» рядом с кнопкой.
**Файлы:** `src/pages/Export.tsx:28-31` — добавить `desc` в объект FORMAT_TEXT.

#### Размеры заголовков и фон в модалке экспорта

**Исследовать:** 1) Открыть `/books/:id/export` → посмотреть на соотношение заголовков секций и контента. Шрифт 10.5px — это осознанный label-стиль (как в design.md), не нужно увеличивать. 2) Чёрный фон — `src/pages/Export.tsx` обёртка страницы: это намеренно (имитация overlay модалки на тёмном фоне). Если выглядит неожиданно — рассмотреть blur/dimm overlay вместо solid black.

**Что сделать:** реализовывать не раньше 100 платящих пользователей. Варианты бэкенда: Supabase Realtime с Y.js, Hocuspocus на Fly.io/Timeweb. TipTap v3 поддерживает Y.js нативно.

**Deps:** §7 (базовое соавторство)

### §36. Снапшот при смене статуса главы — нужно ли объединять?

**Что это:** вопрос о связи статуса главы (черновик / в работе / готово) и Named Snapshots.

**Варианта два, нужно обдумать:**

1. **Авто-тост при смене на «Готово»:** при переводе главы в статус «Готово» — показывать ненавязчивый тост «Зафиксировать версию?» с кнопкой «Сохранить». Нажал — создаётся именованный снапшот «Готово · [дата]» без открытия панели версий. Отклонил — ничего не происходит.

2. **Оставить раздельно:** статус — это пометка для навигации и структуры, снапшот — точка возврата текста. Разные цели, разные триггеры. Объединение создаёт неожиданное поведение.

**Не делать сейчас.** Вернуться после того как появятся реальные пользователи — они покажут, хотят ли они этого сами.
