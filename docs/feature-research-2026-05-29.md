_Дата: 2026-05-29. Изучено: Obsidian, Notion, Roam, Scrivener, Ulysses, iA Writer, Bear, Plottr, World Anvil, Campfire, Bibisco, Sudowrite, NovelAI, Novelcrafter, ProWritingAid, Hemingway App, 4theWords, Pacemaker, Beta Books._

## 1. Контекст: философия продукта как фильтр

Прежде чем смотреть на фичи — напоминание о том, кем мы не хотим быть:
- **Не Scrivener** — функционально перегружен, компиляция занимает курс за $100
- **Не Notion/Obsidian** — слишком блочно, слишком настраиваемо, слишком "инструмент, а не студия"
- **Не Google Docs** — корпоративный, безликий, для документооборота

Мы: **Literary · Precise · Immersive.** Каждая фича должна проходить тест: *делает ли она интерфейс невидимым, или наоборот — навязывает себя?*

## 2. Ключевые инсайты по инструментам

### Obsidian
Самое важное открытие: писатели используют Obsidian **не как редактор, а как живую базу мира** через механику backlinks. Когда в сцене упоминается «Дэмиен» — в карточке Дэмиена автоматически появляется список всех сцен. Без ручного ведения. Плагин Dataview позволяет делать запросы: "все сцены с POV=Анна и статусом=черновик". **Граф связей** красивый, но малополезный — реально ценен именно List of backlinks для конкретного объекта.

Главная боль: нужно самому строить систему с нуля. Новичок тратит недели на настройку вместо письма.

### Notion
Реляционные базы "из коробки" — главная причина оставаться. Но **самая частая жалоба**: "организуешь вместо того чтобы писать". Notion тренирует принимать структурные решения до письма. Пишут в другом редакторе, в Notion — только план.

### Scrivener
Дважды лучший на рынке: **структура проекта** (Binder) и **версионирование** (Snapshots). Research Folder — хранилище всего референсного материала внутри одного .scriv-файла. Revision Mode с 5 цветами — уникальный инструмент для нескольких проходов редактуры. Но кривая обучения такова, что продаются отдельные курсы по нему.

### iA Writer
Единственный конкурент с **Syntax Highlight по частям речи** — прилагательные оранжевые, глаголы зелёные, наречия синие. Не правит, не советует — просто делает структуру языка видимой. Писатели называют это "the best editing tool I've never seen anywhere else". Style Check находит клише и заполнители прямо в тексте.

### Ulysses
Writing Streak — непрерывные дни письма с бейджами. Самый детальный трекинг целей: слова / символы / предложения / минуты чтения. Прямая публикация в WordPress/Ghost прямо из редактора.

### Plottr
Визуальный таймлайн: строки = сюжетные линии, колонки = сцены. Цвета линий. Drag & drop. 40+ шаблонов структур (Hero's Journey, Save the Cat). Reverse-outline через AI: загружаешь готовый текст — получаешь структурный план. **Только планировщик, не редактор** — потом переносится в Scrivener/Word.

### World Anvil
Уникальная **система Secrets/Spoilers**: внутри любой статьи можно спрятать блок-секрет. Автор видит всё. Читатели — только то, что открыто. Reading View vs Author View — две версии одной страницы. Интерактивные карты с пинами, ведущими в статьи локаций.

### Campfire
17 модулей: Characters, Manuscript, Locations, Maps, Timelines, Magic, Languages, Religions... Всё перелинковано. **Relationship Maps** — визуальная схема связей между персонажами. Клик на имя → карточка. Для серийных авторов — единая база для всех книг.

### Bibisco
138 вопросов о персонаже в 6 категориях. Самое глубокое: разделение **Interior Life** (что думает и чувствует внутри) vs **Exterior Life** (как ведёт себя снаружи). Формат интервью — программа "разговаривает" с персонажем. Relationships Matrix. Event Timeline персонажа — хронология жизни ДО начала истории.

### Sudowrite
**Describe** — выделяешь слово → получаешь варианты сенсорных деталей по 5 чувствам (запах, звук, осязание, вкус, зрение). **Rewrite с тональностью** — "сделай мрачнее", "покажи, не рассказывай", "сократи вдвое". Писатели хотят эти фичи в любом редакторе, а не только в Sudowrite.

### Novelcrafter
**Codex** — база данных мира с ключевыми словами. При генерации AI-текста контекст Codex автоматически инжектируется. Редактор замечает упоминание персонажа → показывает его карточку. Кросс-проектная память для серий.

### ProWritingAid
**Pacing Report** — показывает, где в тексте провисает темп (можно визуализировать как тепловую карту плотности). **Consistency Report** — ловит grey/gray, ошибки в именах, теги диалога. Character Name Consistency — одинаковость имён по всей рукописи.

### 4theWords / Pacemaker / TrackBear
**4theWords**: геймифицированное письмо — "сражения с монстрами" через набор слов. Streak = 444 слова/день минимум. **Pacemaker**: лучший инструмент для completion ETA — adaptive pacing пересчитывает план каждый день. **TrackBear**: multi-project трекер с Historical trend graphs.

### Beta Books
Специализированная платформа для бета-ридеров: chapter-by-chapter чтение, inline highlights, emoji-реакции, аналитика "до какой главы дочитали". **Нет ни одного основного редактора с встроенным beta reader mode**.

## 3. Gap-анализ: чего нет нигде (или реализовано плохо)

| Gap | Где частично есть | Насколько болезненно |
|---|---|---|
| **Writing Heat Map** (GitHub-style) | Только плагины Obsidian | 🔴 Высоко — retention-механика отсутствует у всех |
| **Ambient sounds** | Только Focused (macOS, нишевой) | 🟡 Средне — писатели используют Noisli/Brain.fm параллельно |
| **Beta reader mode** | Beta Books (отдельный сервис) | 🔴 Высоко — ни один редактор не имеет встроенного |
| **Linked worldbuilding + рукопись** | Campfire (разделяет) | 🔴 Высоко — переключение контекста раздражает |

## 4. Приоритизированные рекомендации

Все фичи разбиты на три уровня. Критерии: impact для писателя, fit с философией "невидимого интерфейса", реалистичность реализации на текущем стеке (Vite + React + TipTap + Supabase).

### УРОВЕНЬ 1 — Делать в первую очередь

#### 1.1 Writing Heat Map (GitHub-style calendar)

**Что:** Календарная тепловая карта — каждый день окрашен интенсивностью по количеству написанных слов. Видна прямо на дашборде книги или в профиле автора.

**Почему первым:** Это единственный **retention-механизм**, которого нет ни у одного крупного конкурента. Streak (цепочка дней) — психологически мощный инструмент. Писатели не хотят прерывать цепочку. GitHub доказал: люди меняют поведение ради зелёных клеток.

**Как реализовать:** Таблица `writing_sessions (user_id, book_id, date, words_written)`. При каждом autosave — дельта слов за сессию. На дашборде: SVG-сетка 52 недели × 7 дней, oklch-тонирование от 0 до max слов. Tooltip при наведении: "14 мая — 1 247 слов". Стрик-счётчик: "🔥 12 дней подряд".

**Сложность:** Средняя. Бэкенд простой (одна таблица + RLS). Визуализация — SVG без библиотек.

---

#### 1.2 Backlinks: автоматические связи персонаж ↔ главы

**Что:** Когда автор упоминает имя персонажа в тексте главы — связь создаётся автоматически. В карточке персонажа появляется вкладка "Главы" со списком всех глав, где он встречается.

**Почему первым:** Это главная причина, по которой писатели держат Obsidian открытым параллельно. Реализация убирает необходимость в стороннем инструменте. **Уже частично запланировано как §12** — но там описана сложная морфологическая реализация. Минимальная версия (поиск по aliases) значительно проще и уже даёт 80% ценности.

**Как реализовать (MVP):**
1. На карточке персонажа — поле `aliases text[]`: список имён для поиска ("Дэмиен", "Дём", "Дэм").
2. Фоновый scan при сохранении главы: ищет aliases в plain text TipTap JSON.
3. Записывает найденные совпадения в `chapter_characters` с флагом `auto_detected = true`.
4. Вкладка "Главы" в карточке: ручные связи + авто с пометкой "(авто)".

**Не делать сейчас:** морфология (pymorphy2), semantic search, NLP — это отдельный продукт.

**Сложность:** Средняя. Парсинг TipTap JSON уже используется для счётчика слов.

---

#### 1.3 Streak + Writing Goals — расширение

**Что:** К существующей дневной цели по словам добавить:
- **Streak counter** — "🔥 5 дней подряд". При достижении 7 / 30 / 100 дней — небольшая анимация.
- **Weekly summary** — всплывающий тост в понедельник: "На прошлой неделе — 4 891 слово".
- **Completion ETA** — "При текущем темпе (847 слов/день) вы закончите книгу через ~43 дня".

**Почему первым:** Ulysses и 4theWords доказали: streak = мощная retention-механика. Toast при достижении дневной цели уже реализован (roadmap §32 закрыт). Streak — следующий логичный шаг.

**Как реализовать:** `writing_sessions` (из п.1.1) даёт данные. Streak = MAX(consecutive days with words_written > 0). ETA = (target_words - current_words) / avg_words_per_day_last_7.

**Сложность:** Низкая — если Heat Map (1.1) реализован, данные уже есть.

---

#### 1.4 Быстрая карточка объекта при наведении (Lorebook-style)

**Что:** При наведении на имя персонажа/локации в тексте — всплывает мини-карточка с фото, именем, ролью и 2-3 ключевыми чертами. Клик раскрывает полную карточку в правой панели.

**Почему важно:** Это устраняет самую частую причину прерываться при написании — "кто такой этот персонаж, какие у него глаза?". Novelcrafter реализовал это как главную фичу Codex. iA Writer — через Content Blocks. Все продвинутые писательские инструменты двигаются в этом направлении.

**Как реализовать:** TipTap Extension — DecoratorPlugin, который ищет aliases персонажей в тексте и оборачивает их в `<span data-character-id="...">`. При hover — Floating UI тултип с данными из кэша персонажей.

**Связано с:** 1.2 (aliases нужны там же). Реализация Backlinks даёт нужные данные.

**Сложность:** Средняя. TipTap декораторы — задокументированная механика.

### УРОВЕНЬ 2 — После монетизации и первых пользователей

#### 2.1 Focus Mode — подсветка по предложению/абзацу

**Что:** В режиме письма — выбор гранулярности фокуса:
- **Абзац:** весь остальной текст приглушается до opacity 0.3
- **Предложение:** приглушается всё кроме текущего предложения

Плюс **Typewriter Scrolling** — текущая строка фиксирована по вертикали.

**Почему важно:** iA Writer и Ulysses сделали это killer feature для рынка minimalist editors. У нас уже есть page mode (режим "страницы") — Focus внутри него станет мощным аргументом для аудитории, которая сейчас держит iA Writer открытым.

**Как реализовать:** TipTap NodeView + CSS-анимации. `prefers-reduced-motion` уже уважается в дизайн-системе.

**Сложность:** Средняя. CSS-решения для dim хорошо задокументированы.

---

#### 2.2 Syntax Highlight по частям речи (режим редактуры)

**Что:** Опциональный режим редактирования — цветовая подсветка частей речи прямо в тексте:
- **Прилагательные** — оранжевые: слишком много = перегруженный текст
- **Наречия** — синие: сигнал для Стивена Кинга ("kill your adverbs")
- **Глаголы to be** — зелёные: пассивный залог
- **Союзы** — жёлтые: слабые связи

Не меняет текст, не экспортируется. Только при включённом режиме редактуры.

**Почему важно:** Единственный конкурент с этой фичей — iA Writer (только Mac). Нет у Scrivener, нет у Ulysses, нет у Notion. Для русского рынка — вообще первый инструмент с этим. Уникальный дифференциатор.

**Как реализовать для русского:** Подключить `compromise-ru` или `yandex-mystem` API для POS-tagging. TipTap декораторы для подсветки. Можно начать с regex-правил для наречий на -но/-нно/-ски/-цки/-жды и глаголов "быть/является/являлся".

**Сложность:** Средняя-Высокая. Русская морфология сложнее английской. MVP — только наречия и пассивный залог через regex.

---

#### 2.3 Снапшоты с именами (Named Snapshots)

**Что:** Расширение существующего восстановления версий. Добавить:
- Ручное создание снапшота с именем: "До переработки концовки", "Черновик редактора 1"
- Список снапшотов в боковой панели с датой и количеством слов
- Diff между любым снапшотом и текущей версией (уже частично реализован)

**Почему важно:** Scrivener Snapshots — одна из главных причин, по которой профессиональные авторы платят за Scrivener. Страх потерять "ту самую версию главы до правок" — реальный. У нас уже есть автовосстановление, но нет ручного named snapshot.

**Сложность:** Низкая — таблица `chapter_snapshots` уже существует по логике. Нужно добавить поле name и UI для создания вручную.

---

#### 2.4 Relationship Map — визуальный граф персонажей

**Что:** Визуальная схема связей между персонажами вместо (или вместе с) матрицей. Узлы = персонажи, рёбра = отношения с подписями. Расположение — force-directed graph. Интерактивный: клик на персонажа → его карточка.

**Почему важно:** Campfire реализовал это как killer feature. Bibisco — только матрица (скучно). Писатели хотят видеть "паутину мира" одним взглядом. Особенно актуально для больших ансамблей (fantasy, семейные саги).

**Как реализовать:** `character_relationships` таблица уже в roadmap (§13). Граф — через `@visx/graph` или `vis-network`. Данные уже будут после реализации двусторонних связей.

**Сложность:** Средняя — если §13 реализован, граф = отдельный view поверх готовых данных.

---

#### 2.5 Ambient Sounds — звуки для фокуса

**Что:** В toolbar редактора — кнопка 🎧. Открывает мини-панель с выбором атмосферы: Кафе · Лес · Дождь · Костёр · Библиотека. Ползунок громкости. Автопауза при выходе из редактора.

**Почему важно:** Это рыночный gap — ни одно крупное приложение не реализует. Писатели используют Noisli, Brain.fm или YouTube параллельно. Встроенные ambient sounds — мощный аргумент для immersive experience, который соответствует нашей философии.

**Как реализовать:** Web Audio API + несколько looping .ogg файлов (лицензия CC0 — достаточно на freesound.org). Хранить выбор в localStorage. ~5-7 аудиофайлов, каждый ~500KB.

**Сложность:** Низкая. Технически тривиально. Основное — подобрать качественные звуки.

---

#### 2.6 Pacing Visualization — тепловая карта темпа

**Что:** На экране оглавления (Outline / Structure) — цветовая индикация глав по длине/темпу. Короткие главы = более холодный цвет, длинные = тёплый. Или наоборот — по плотности событий (количество глав → отдельный показатель).

**Упрощённая версия:** Sidebar с горизонтальными bar-ами по длине глав. Сразу видно: три длинные подряд, потом одна короткая — нормально? Или есть "провал" в середине?

**Почему важно:** ProWritingAid Pacing Report — один из самых ценимых отчётов. Писатели хотят видеть ритм романа без инструментального анализа. Это визуальная информация, а не совет.

**Сложность:** Низкая. Данные уже есть (word_count по главам). Только CSS визуализация.

### УРОВЕНЬ 3 — Дифференциаторы (сложно, но уникально)

#### 3.1 Beta Reader Mode — режим читателя

**Что:** Владелец книги выдаёт ссылку бета-ридеру. Бета-ридер видит книгу в режиме чтения (не редактирования): может выделить любой фрагмент и оставить комментарий. Автор видит все комментарии на панели с фильтрацией по читателю и главе.

**Почему важно:** Рыночный gap — только Beta Books (отдельный сервис, $15/мес). Встроенный beta reader mode = убийца целого класса инструментов. Это мощный аргумент для профессиональных авторов, которые работают с редакторами и бета-ридерами.

**Как реализовать:** Таблица `book_shares (book_id, token, reader_name, expires_at)`. Комментарии = `reader_comments (share_id, chapter_id, selection_start, selection_end, text)`. Автор видит комментарии в режиме annotations на полях. TipTap уже поддерживает highlight decorations.

**Сложность:** Высокая. Но дает Pro-tier дифференциатор.

---

#### 3.2 Interior Life vs Exterior Life для персонажей

**Что:** В карточке персонажа — два отдельных поля/раздела:
- **Внутренний мир** — что думает, чувствует, о чём мечтает, чего боится (невидимо другим персонажам)
- **Внешнее поведение** — как ведёт себя, что говорит, как выглядит в глазах других

Плюс поле **Разрыв**: где внутреннее и внешнее расходятся — это источник конфликта и характеризации.

**Почему важно:** Bibisco сделал это своей главной фичей и собрал 200 000+ пользователей именно на этом. Это психологически правильный фреймворк для построения живых персонажей. Literary fiction авторы оценят это выше любой другой фичи в картотеке.

**Сложность:** Низкая. Только UI + новые поля в `characters` таблице.

---

#### 3.3 Story Structure Templates

**Что:** При создании книги — опциональный выбор шаблона структуры:
- Свободная (без шаблона)
- Трёхактная структура (Act I / II / III)
- Hero's Journey (12 этапов)
- Save the Cat (15 beats)
- Снежинка (Snowflake Method)

При выборе — в Outline/Structure автоматически создаются главы-заглушки с подсказками: "Act I: Setup — здесь знакомим с героем и миром".

**Почему важно:** Plottr имеет 40+ шаблонов — это главная причина, по которой начинающие авторы платят за него. Опытным авторам — не нужно. Но для аудитории "первый роман" — это снятие страха белого листа. Конкурент ScreenCraft, Novel Factory строятся именно на шаблонах.

**Сложность:** Низкая. Предзаполненные данные при создании книги.

## 5. Что НЕ делать (и почему)

| Фича | Почему не делать |
|---|---|
| **AI-генерация прозы** | Меняет суть продукта. Мы — студия, не соавтор. Sudowrite уже занял нишу. |
| **Compile с 40 настройками** | Anti-reference прямо в product.md. Экспорт уже есть и работает. |
| **17 модулей worldbuilding** (как Campfire) | Перегрузка против нашей философии. Magic Systems, Languages, Religions — для 1% пользователей. |
| **Граф всего мира** (Global Graph как в Obsidian) | Красиво, но бесполезно при росте. Local Graph (связи одного объекта) — полезен. |
| **Real-time collaboration** | Требует Y.js + Hocuspocus, меняет архитектуру. Только после 100 платящих (уже в roadmap). |
| **Name Generator** | Low impact, легко гуглится. Не наша задача. |
| **Publishing workflow** (публикация в WordPress) | Не наша аудитория. Мы — до публикации, не про неё. |
| **Семантический поиск / NLP** | Стоимость vs. ценность. Aliases (п.1.2 MVP) даёт 80% ценности за 5% сложности. |

## 7. Самый важный вывод

Самая частая жалоба на **все** инструменты — одна и та же, независимо от продукта:

> _"Я провожу время, организуя своё письмо, вместо того чтобы писать."_

Это жалоба на Notion, на Obsidian, на Scrivener (компиляция), на World Anvil (кривая обучения). **Это наш главный дифференциатор по умолчанию** — если мы не сломаем его добавлением лишних фич.

Каждая фича из Tier 1 работает по принципу: **структура возникает сама по мере письма, а не требует настройки до него**. Heat Map считается автоматически. Backlinks строятся сами. Карточка всплывает по hover. Streak не требует ручного ввода. Автор просто пишет — инструмент работает.

Это и есть "Literary · Precise · Immersive" в действии.
